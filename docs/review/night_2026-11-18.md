What I changed, and why:

1. **REF and ALT.** PLINK 2 assigns REF and ALT from the data when it reads a text file. For `5:5001011` it chose REF C, ALT G (the supplied files had G and C). For `22:22001617` it chose REF A, ALT G (supplied: G and A). So the `.bed` bytes 7 and 10 changed (`ca` to `3a`, `36` to `c6`). I replaced `.bed`, `.bim`, `.fam`, `.pgen`, `.pvar`, `.psam` and the VCF with the PLINK 2 output. The genotypes are the same: I compared the `.ped` exported from the new `.bed` with `06_plink_ped/example.ped` as unordered pairs, and all 32 genotypes match. I updated the README table, `bed_byte_by_byte.md`, the hex line of `07_plink_bed/README.md` and `expected_alt_counts.tsv` (the ALT counts of the two variants are now 2 minus the old counts). I added a paragraph to the main README that says why REF is "provisional" (the VCF flag `PR`).
2. **`--export A` counts the REF allele by default in this PLINK 2 build**, so the command in `conversions.md` did not give the ALT counts of the table. The working command is `plink2 --bfile example --export A include-alt --export-allele alt_alleles.txt --out example_check`. I added `scripts/alt_alleles.txt` (the ALT allele of each variant). The counts then match the table for all 32 genotypes.
3. **`--export vcf` writes sample names as `S01_S01`.** Added `id-paste=iid` in every command (README files and `conversions.md`).
4. **`--vcf ... --make-pgen` fails for chromosome X** ("no sex information"). A VCF has no sex. The commands now read `--psam example.psam`, and the result is a `.pgen` identical to the supplied one.
5. The VCF now has the header that PLINK 2 writes (`##fileformat=VCFv4.3`, a file date and the `PR` flag). The text in `09_vcf/README.md` says that males on X may be haploid (`0`, `1`), which is what PLINK 2 writes.

Position in the repository: `examples/formats/array_to_plink/` (the repository allows tiny invented examples only in `examples/formats/`). The folder is 36 KB, so the total of that folder stays below the 100,000 bytes limit of `scripts/package_project.py`. The packaging tests pass. The files are public and not behind the data password.

New test: `scripts/tests/test_format_examples.py` (alleles agree in `.bim`, `.pvar`, VCF and the expected counts; the bytes of the `.bed` give the expected ALT counts; the byte table lists the real bytes).

Site: the File formats page has one box for each format in the order IDAT, manifest, GTC, Final Report, `.lgen`, `.ped`, `.bed`, `.pgen`, VCF. Each box says what the format contains, who makes it, the columns (from the README), a text preview and a download button for each text file, and the next conversion.
