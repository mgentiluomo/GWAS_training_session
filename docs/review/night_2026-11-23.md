## Phase 1. Generator and truth build (branch `course/module-a-data`)

### Code changes

`scripts/author/make_sim2026.py`:

- `TRUTH_MARGIN = 1_000_000` and `MAX_INDEL_ALLELE = 50`. The truth regions are the old regions plus 1 Mb on
  each side: chr18 36,792,715 to 39,292,715 (L4 at 38,042,715) and chr22 35,000,000 to 37,500,000.
- The old `regions` (L4 plus or minus 250 kb, chr22 36.0 to 36.5 Mb) are unchanged and still go to
  `extract_donors` and `plant_problems`. This matters: `plant_problems` keeps the array sites within 250 kb of
  these regions clean, so wider regions there would have changed the planted problems and the main-path data.
- New `extract_region_donors`: a separate PLINK 2 fileset (`work/donors_regions`) with the donors in the
  truth regions only, biallelic SNVs and indels, IDs `chrom:pos:ref:alt`, alleles of at most 50 bases
  (`--new-id-max-allele-len 50 missing`). The fileset of the array sites (`work/donors`) is made by the same
  command as before.
- `simulate_genomes`: on chromosomes with a truth region, the dense-region columns are merged into the array
  columns by `core.merge_columns` (array columns keep their order; a duplicated ID keeps the array copy). In a
  region, every variant with both alleles among the donor-pool haplotypes is kept (before: template MAF at
  least 0.01). A guard stops the build if a region changed the first or last site of a chromosome. This is why
  the main path stays the same: each chromosome has its own random stream, and the mosaic and meiosis
  breakpoints depend only on the cM span of the chromosome, not on the number of columns.
- `write_imputation` (simulated dosages) is replaced by `write_imputation_truth`: true phased genotypes of the
  final cohort (1,811) at every region variant, `instructor/imputation_truth_chr18.vcf.gz` and `_chr22`, with
  the INFO flag `ARRAY` on array sites. `imputation` is no longer in `STUDENT_DIRS`.
- `donors_all.keep` is copied to `instructor/`, and its SHA-256 goes into `build_record.json` (`module_a`).
- The student `README_simulated.txt` text is unchanged on purpose: it still mentions imputation output, but
  changing it would change a student file. The release staging writes its own README anyway.

`scripts/author/sim2026_core.py`: new pure functions `region_rows_ok`, `merge_columns`, `truth_vcf_lines`.
The functions of the old simulated dosages stay (their tests still run) but the build no longer calls them.

Tests (`scripts/author/tests/test_sim2026.py`): 4 new tests (row filter, column merge, truth VCF lines,
no student imputation folder and unchanged planting regions). Result: 40 of 40 passed.

### Identity proof

Script `C:\WEB_site\data_sources\module_a_work\identity_check.py` (reads only).

- Student files: old build 57 (4 in `imputation/`), new build 53. **51 identical byte for byte, 2 different,
  none missing, none added.**
- The 2 different files are PLINK logs written by `verify_sim2026.py`:
  `checkpoints/4.6/sim2026_after_variant_qc.log` and `checkpoints/5.6/sim2026_after_ancestry.log`. They differ
  only in the output folder, the working directory, the start and end time and PLINK's clock-based random seed.
  With those lines removed they are identical. Their `.pgen`, `.pvar` and `.psam` are identical.
- Release manifests: of the 108 files of `data-2026.1`, the same 24 SHA-256 values are found in the old and
  in the new build; of the 111 files of the 2026.2 staging, the same 17. So the two logs are in neither
  release, and both manifests are coherent with the new build.
- Truth: at the 1,536 (chr18) and 2,115 (chr22) variants of the old truth files, the new files have the same
  samples in the same order and **no genotype difference**.

**Decision (to confirm).** The rule was: stop if any student file differs. Two log files differ, but no rerun
can make them identical, not even with the old code, because they record the time and the folder of the run.
Every data file is identical. I treated the proof as passed and went on with the new build. As a safeguard,
the study input of phase 3 comes from the 5.6 fileset, which is byte-identical in both builds. Only the truth
comparison uses the new build. If you do not accept this, the truth tables of phase 3 must be set aside.
