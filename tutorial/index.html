What you need

  • Basic experience opening a table in R.
  • Your own Windows, macOS or Linux computer.
  • R, RStudio and PLINK 2 for the analytical work.

You can read the tutorial and try its browser exercises without installing the analysis software.

What you will produce

  • An auditable QC count table.
  • PCA and an explicit sample list.
  • Association results and a short interpretation.

The modules can be used separately or combined. One suggested teaching route uses three four-hour sessions, including breaks.

Practice data, clearly labelled. This web walkthrough uses a simulated dataset: 600 samples and 6,000 variants. The original class data use a separate access route. Demo results cannot support a claim about a real disease.

Use the modules across courses

These are independent teaching materials by Manuel Gentiluomo for students at the University of Pisa. Use a single topic, follow the complete GWAS pathway, or return to an example for self-study.

One possible teaching context is Omics: Biotechnology and AI for Health (552EE), in the MSc in Biotechnologies and Applied Artificial Intelligence for Health. The resource has a broader scope and can support other genetics, genomics, biotechnology and bioinformatics teaching.

Choose the preparation and file-format sections if you are new to the tools. If you already know them, move to the analytical modules and optional challenges. Teaching time and module selection can be adapted to each course.

Before the class

A working starting point.

Keep your computer in your preferred language. We use explicit file conventions and a single RStudio project.

1. Download the complete project

Download the ZIP and extract it into a writable local folder. Open GWAS_course.Rproj. Keep its folders together; do not move individual notebooks into a new folder.

Download the RStudio projectBrowse the source on GitHub

This preview points to the review branch. The main branch is not yet the revised course.

2. Install R and RStudio

Install R first, then RStudio Desktop. Open the project and find the R console: it usually has a > prompt.

R console · check the project
getwd()
file.exists("config.R")
Check: the second command returns TRUE. If not, reopen the project instead of editing paths in every lesson.

3. Add PLINK 2 for your system

Download from the official PLINK 2 page, extract the archive, and put the executable in the project’s bin/ folder. The tested Linux build is beta 1.4, 7 November 2026; record the actual build you use.

Windows

Select the appropriate 64-bit build. Put plink2.exe directly in bin/. Windows may hide known filename extensions: check the file type and avoid accidentally naming it plink2.exe.exe.

macOS

Select ARM64 for Apple Silicon or the matching Intel build for an Intel Mac. Put plink2 in bin/. If necessary, run Sys.chmod("bin/plink2", "0755") in the R console. Follow the standard macOS approval process for a trusted official download.

Linux

Select a build compatible with the CPU. Put plink2 in bin/. If necessary, run Sys.chmod("bin/plink2", "0755") in the R console. A working executable on PATH is also supported.

The analytical workflow has been executed on Linux. The Windows and macOS instructions still require checks on those systems. Do not disable system security to run a download.

4. Create or download the demo inputs

Leave mode = "demo" in config.R. Create the data in the R console:

R · run in RStudio
source("scripts/create_demo.R")

The final table should report 600 samples and 6000 variants. If you cannot generate it yet, download the same input files and extract them into the project root, preserving the data/demo/ path.

R · run in RStudio

The setup sets decimal display to a point in the current R session. It does not change your operating-system language. The importer rejects ambiguous numeric fields rather than guessing.

Why a comma is not always a decimal mark

In one file, 1,234 may mean one point two three four; in another, one thousand two hundred thirty-four. A blanket replacement can corrupt data. Confirm the documented delimiter and decimal convention before converting an external file.

Step 02

Three files describe one genotype dataset.

The binary calls, variant information and sample information belong together. Their order matters: a matching filename alone does not prove that the three files come from the same release.

.bed

Packed genotype calls. Do not open or edit it as a text table.

.bim

One row per variant: location, identifier and two alleles.

.fam

One row per sample: identifiers, parents, sex and phenotype.

Step 04

Look at missingness before choosing a cutoff.

A missing genotype is an uncalled sample–variant entry. Sample missingness uses variants as the denominator; variant missingness uses samples. A 5% missingness threshold corresponds to a 95% call rate.

Explore the diagnostic

Move the sample-missingness threshold.

594samples meeting this criterion
6samples above the threshold

Calculated from the 600 actual demo baseline missingness values. This browser exercise changes no files. Full-pipeline counts can differ after earlier filtering changes the denominator.

Step 05

Apply one filter, then count.

The course uses teaching thresholds: variant missingness 5%, sample missingness 10%, and MAF 1%. These are choices to examine, not values to transfer automatically to any study.

A. Variant missingness: --geno 0.05

Remove variants with missing calls in more than 5% of samples.

C. Minor allele frequency: --maf 0.01

Remove variants with minor allele frequency below 1% in the current sample set. MAF is an allele frequency, not the proportion of people carrying the allele.

Why can the order matter?

Each filter is calculated using the samples and variants present at that step. Removing poorly called variants can reduce a sample’s measured missingness; removing samples can change allele frequencies. Keep the order and its count table with your results.

Step 06

Review unusual heterozygosity.

Estimate the inbreeding coefficient on common, approximately independent variants. LD pruning limits the influence of highly correlated markers. The pruned set is for diagnostics, not automatically the final association dataset.

R · run in RStudio
prune <- file.path(cfg$qc, "prune")
run_plink(cfg, c("--bfile", maf, "--maf", "0.05", "--indep-pairwise", "200", "50", "0.2",
                "--out", prune), paste0(prune, ".prune.in"))
run_plink(cfg, c("--bfile", maf, "--extract", paste0(prune, ".prune.in"),
                "--het", "--out", file.path(cfg$qc, "heterozygosity")),
          file.path(cfg$qc, "heterozygosity.het"))
het <- read_ws(file.path(cfg$qc, "heterozygosity.het"))
summary(as.numeric(het$F))
R · run in RStudio
hist(as.numeric(het$F), breaks = 30, main = "Review heterozygosity", xlab = "F coefficient")
An unusual coefficient can reflect technical problems, ancestry or inbreeding. A pooled mean ±3 SD rule can remove valid samples from a heterogeneous cohort. This walkthrough reports the diagnostic without automatic heterozygosity exclusions.
Going further: what else would you ask before excluding a sample?

Review call quality, batch, contamination evidence, population structure and whether the coefficient was estimated using appropriate allele frequencies. Record the rationale and repeat downstream analysis after any justified exclusion.

Step 07

Avoid treating close relatives as independent.

The simple association models later in the course assume independent observations. KING estimates genetic kinship and selects a subset avoiding pairs above the chosen threshold.

RelationshipApproximate KING kinship
Duplicate / identical genotype0.50
First degree0.25
Second degree0.125
Third degree0.0625

The teaching cutoff is 0.0884, screening close relationships through roughly the second degree. Estimates are variable; KING kinship is not the same quantity as PI_HAT.

R · run in RStudio
king <- file.path(cfg$qc, "relatedness")
run_plink(cfg, c("--bfile", maf, "--extract", paste0(prune, ".prune.in"),
                "--king-cutoff", plink_number(cfg$kinship), "--out", king), paste0(king, ".king.cutoff.in.id"))
final <- file.path(cfg$qc, "qc_final")
# Apply the sample list to ALL QC-passing variants, not just the pruned subset.
run_plink(cfg, c("--bfile", maf, "--keep", paste0(king, ".king.cutoff.in.id"),
                "--make-bed", "--out", final))
record_counts(cfg, final, "05_unrelated")
read.delim(file.path(cfg$qc, "sample_variant_counts.tsv"))
Check: the demo finishes with 592 samples and 5920 variants. Two simulated duplicate pairs lead to two exclusions. Apply the retained sample list to all QC-passing variants, rather than keeping only the LD-pruned markers.
How would sample selection change in a research study?

Call quality, phenotype completeness and the study design can affect which relative should be retained. A mixed-model strategy may instead accommodate related observations. The automatic teaching subset is not a universal sample-priority rule.

Module 01 · Practice

Make the decisions yours.

Predict first. Run a separate comparison if you can. Use the explanation only after you have tried.

1. Call rate is not missingness

A new sample has a call rate of 94%. A protocol keeps samples with missingness at most 0.08. Does it pass this criterion? Show the conversion.

Reveal a worked explanation

Its missing fraction is 1 − 0.94 = 0.06, or 6%. It passes the 8% missingness criterion. This says nothing about whether it passes other QC criteria.

2. A stricter cutoff

Before running a new command, predict what reducing mind from 0.10 to 0.05 can do to the retained sample set for the same input. Use a new output prefix such as 03_mind_stricter; do not overwrite the core result.

A hint, without running it

The same input and denominator are essential. Ask whether a sample failing the original rule could pass a more restrictive version of that rule.

Reveal the reasoning

The number retained cannot increase for the same fixed input, though it may stay equal. The exact difference depends on the data. Repeating the whole pipeline can change other estimates, so separate the one-step comparison from a complete rerun.

3. The mixed file set

A BED file downloaded yesterday is combined with a BIM from another release. The names match and both files open. What would you check before running QC?

Reveal the reasoning

Check provenance and release, sample/variant order, dimensions and the BED signature/expected byte count. Equal dimensions alone cannot prove that the biological records are matched. Obtain a known matching set rather than relabelling files to bypass a check.

4. A problematic import

An exported file has header FID;IID;Age and a value 24,5. Explain why renaming it to .tsv is insufficient. What information is needed before conversion?

Reveal the reasoning

Renaming does not change delimiters, decimal marks or encoding. Confirm the documented semicolon separator, decimal comma, missing-value coding, text encoding and identifier handling, then import with those settings and validate a new canonical output. Do not replace all commas blindly.

Troubleshooting

Keep the first error.
Find a way back in.

A technical problem does not need to end your participation. You can read the examples, interpret outputs and rejoin from a matching checkpoint.

When a chunk stops

  1. Do not run later chunks yet.
  2. Read the first error, not just the last line.
  3. Inspect the input or log named in that message.
  4. Use the relevant check below, or a checkpoint if the class is moving on.
R cannot open R/course.R

Open the complete RStudio project. In the console, file.exists("config.R") should be TRUE. Do not move the notebook into a separate folder or translate folder names by hand.

PLINK 2 was not found

Extract the executable from its ZIP and place it directly in bin/: plink2.exe on Windows, plink2 on macOS/Linux. A PLINK 1.9 executable is not sufficient. Confirm that the build matches your OS and CPU.

A downloaded program cannot execute

Check CPU architecture, file permissions and the operating system’s normal approval process for a trusted official download. On macOS/Linux, Sys.chmod("bin/plink2", "0755") grants executable permission to that file. Do not disable security globally.

BED header or size does not match

Check whether a login webpage was saved instead of binary data. Confirm that BED, BIM and FAM are from the same release. Obtain the matching set; do not rename unrelated files to pass the check.

The table has one column, or a number is rejected

Check the actual delimiter, decimal mark and text encoding. Course metadata are UTF-8 TSV with decimal points. A semicolon CSV or decimal comma needs a documented separate import. Avoid an Excel open-and-resave round trip on analytical inputs.

Sample IDs are duplicated or do not match

Inspect the FID/IID pairs as text, including initial zeros. Resolve the data provenance. Do not join by row number or discard an identifier to force a match.

A file exists but a variable is not found

Files on disk and objects in R memory are different. Start with the notebook’s setup chunk. If restoring an intermediate package, run the path-variable setup on the Downloads page, then execute the next individual step.

My count differs from the example

Confirm demo mode, the original seed, filtering order and settings. Check the count table and the first differing PLINK log. The published numbers are for the default simulation, not the original study or an intentionally modified exercise.

A path with spaces or other alphabets fails

The course constructs and quotes paths, but platform verification is still needed. Preserve your original copy and try a short writable project location, such as C:/gwas_training on Windows or a gwas_training folder in your home directory. Rerun preflight and retain its report.

Knit fails but individual chunks work

The analytical code and HTML rendering have different dependencies. Run source("scripts/install_packages.R") and check knitr, rmarkdown and Pandoc. RStudio normally includes Pandoc. Continue reading this web tutorial while resolving the preview.

Quick reference

A small glossary
for the practical work.

TermMeaning
GenotypeThe observed alleles for one sample at one position.
FID / IIDThe identifier pair used to match samples across files.
Call rateThe fraction of successfully called genotypes: one minus missingness.
MAFMinor allele frequency in the samples used for the estimate.
LDAssociation between alleles at different loci; linked SNPs can carry correlated information.
LD pruningSelecting an approximately independent subset for an analysis such as PCA.
HeterozygosityThe presence of two different alleles at a diploid locus.
KING kinshipAn estimate of genetic relationship; duplicates are near 0.5 on this scale.
HWEA population-genetic expectation for genotype proportions; departures need contextual interpretation.
PCA / PCPrincipal component analysis and the components summarising genetic variation.
CovariateAn additional predictor, such as age or a PC, included in a statistical model.
OROdds ratio per extra copy of the counted allele in an additive logistic model.
A1The counted allele reported by the association output; do not assume it is always the minor allele.
Confidence intervalA range expressing uncertainty under the model’s assumptions.
p-valueUnder the null model, the probability of a statistic at least as extreme as observed.
CheckpointA matching set of saved files from a defined stage, not a guarantee of scientific validity.
